# AIへの指示ルール

複数のアプリ開発でAI（Claude Codeなど）に作業を依頼する際の共通ルール。
各リポジトリの `CLAUDE.md` にはこのルールへの要約・リンクを置き、
プロジェクト固有の詳細はプロジェクト側のノートに書く。

## 開発ノートの運用ルール

- エラーを解決したら、そのプロジェクトの `docs/<プロジェクト名>/エラー記録.md` へ追記する
- 他のアプリでも起こりそうな一般的なエラー・知見は `docs/shared/エラー解決集.md` にも追記する
- コードや設定を大きく変更したら、そのプロジェクトの `変更履歴.md` を更新する
- 未解決の問題は、そのプロジェクトの `未解決の問題.md` に記録する
- 既存の記録と重複する場合は、新規項目を増やさず既存項目を更新する（同じエラーの再発は「発生日」や「試したこと」を追記する形にする）

## 記録してはいけない情報

- パスワード
- APIキー・トークン・シークレットキー
- 秘密鍵・証明書
- 個人情報（氏名、連絡先、住所など）

これらはノートやコミットメッセージ、コード中のコメントにも書かない。
設定が必要な場合は「どこに・どういう形式で設定するか」という手順のみを記録する
（例: `local.properties` に `API_KEY=...` を追加する、環境変数 `XXX_KEY` を設定する、など）。

## エラー記録のフォーマット

新しいエラーを記録するときは、必ず以下の形式を使う（詳細は各プロジェクトの
`エラー記録.md` / `docs/shared/エラー解決集.md` を参照）。

```
## エラー名

- 発生日:
- 対象プロジェクト:
- 環境:
- エラーメッセージ:
- 発生した操作:
- 原因:
- 試したこと:
- 最終的な解決方法:
- 他のプロジェクトでも使える知識:
- 関連ファイル:
```

## AIに作業を依頼するときの基本方針

- 既存のコードは指示された範囲以外は変更しない
- 大きな変更の前に、影響範囲を確認してから着手する
- 破壊的な操作（force push、履歴の書き換え、ファイル削除など）は事前に確認を取る
- 不明点があれば推測で進めず質問する
- 解決したエラーや変更内容は、作業の一部として必ずノートに反映する

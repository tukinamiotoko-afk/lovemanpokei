# プロジェクト概要

## アプリの目的

「ラブ万歩計」は、歩数計測アプリと「バーチャル彼女育成」を組み合わせた
Androidアプリ。プレイヤーが歩くことでキャラクター「ひかり」との
好感度（ラブレベル）が上がっていき、着替え・ショップ・チャット・日記などの
コンテンツを楽しめる。

- パッケージ名: `com.example.lovemanpo`
- アプリ名（リソース）: `ラブ万歩計`

## 技術スタック

- 言語: Kotlin
- UI: Jetpack Compose（Material3）
- Navigation: Navigation Compose
- ローカルDB: Room（`AppDatabase`, DBファイル名 `love_db`）
- 非同期処理: Kotlin Coroutines
- バックグラウンド処理: Foreground Service（歩数計測） + WorkManager（生存監視）
- AI連携: キャラクターとの会話（恋人モード/フリーチャット）はGoogle Gemini
  モデルを利用。ただし `google.generativeai`（Gradle依存関係, 0.9.0）を
  直接使うのではなく、独自に用意したCloudflare Workers上のプロキシ
  （`callGeminiApi()` 関数, `MainActivity.kt` 内）にHTTP POSTでリクエストを
  送り、そちらの先でGeminiを呼び出す構成になっている。実際のGemini APIキーは
  このリポジトリには含まれず、Workers側で管理されている想定。
  なお `StepRepository.geminiApiKey`（SharedPreferences経由）というプロパティが
  別途存在するが、設定画面などUIからは一切参照されておらず、現状は
  未使用（vestigial）。詳細・注意点は `現在の仕様.md` と
  `未解決の問題.md` を参照。

## アーキテクチャの全体像

```
MainActivity.kt (約6800行・単一ファイル)
  ├─ Compose によるすべての画面 (ホーム/ショップ/着替え/設定/日記/記録 等)
  ├─ アプリの状態管理・ViewModel相当のロジック
  └─ StepRepository 経由でDB/SharedPreferencesにアクセス

StepCounterService.kt   … 歩数計測の本体（フォアグラウンドサービス）
HybridStepTracker.kt    … センサー種別に応じた歩数検知ロジック
StepSyncWorker.kt       … WorkManagerでサービスの生存確認・再起動
BootReceiver.kt         … 端末再起動時にサービスを自動起動
Database.kt             … Room（steps / hourly_steps テーブル）
```

`MainActivity.kt` に画面・ロジックの大半が集約されているため、
機能を追加・修正する際は対象のComposable関数名やコメントで検索するのが
現実的（ファイル分割は未実施）。

## 対象端末・パーミッション

- `minSdk 29`（Android 10）〜 `targetSdk/compileSdk 35`
- 主要パーミッション: `ACTIVITY_RECOGNITION`, `POST_NOTIFICATIONS`,
  `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_HEALTH`,
  `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, `RECEIVE_BOOT_COMPLETED`,
  `INTERNET`, `ACCESS_COARSE_LOCATION`
- Xiaomi/MIUI端末など、電力管理・強制ダークモードの影響を受けやすい
  メーカーROMを意識した対策が複数入っている（`docs/lovemanpokei/エラー記録.md`
  および `docs/shared/エラー解決集.md` 参照）

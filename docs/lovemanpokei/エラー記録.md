## ホーム画面背景画像の読み込みによる起動時クラッシュ（painterResource解決失敗）

- 発生日: 2026-07-16
- 対象プロジェクト: ラブ万歩計
- 環境: 実機（painterResource経由のリソースID解決に失敗する端末。BGM無効化後も
  同一箇所でクラッシュしたため、BGMではなく画像読み込みが原因と特定）
- エラーメッセージ: `Resources$NotFoundException`（Resource ID #0x0）
- 発生した操作: ホーム画面表示時（背景画像のCompose描画）
- 原因: `Image(painter = painterResource(id = bgRes), ...)` によるホーム画面背景の
  読み込みが、端末上でリソースID解決に失敗しクラッシュしていた。
  最初はBGM（`MediaPlayer`）が原因だと疑い、例外保護・無効化・遅延読み込みなどを
  試したが解消せず、BGMを完全無効化しても同じ場所でクラッシュすることを確認して
  原因ではないと判明。最終的にCompose側の `painterResource()` のリソースID解決
  処理自体が原因と判断した。
- 試したこと:
  1. `5bc184f` BGM再生処理（`MediaPlayer.create`/`start`/`release`等）を
     すべて `try/catch` で保護 → クラッシュ解消せず
  2. `6e2bf63` BGM再生処理自体を一時的にコメントアウトして無効化し、
     原因切り分けを実施 → それでもクラッシュが再現し、BGM無関係と判明
  3. `9d8c897` （切り分けの過程で）BGM読み込みをバックグラウンドスレッド・
     遅延実行にする変更も試行
- 最終的な解決方法: `9269ca4` にて、ホーム画面背景の読み込みを
  `painterResource()` から `BitmapFactory.decodeResource()` による直接デコードに
  変更（取得失敗時は `null` を返して非表示にするだけにし、例外を握りつぶす）。
  BGM機能はコメントアウトを解除して元に戻した。
  ```kotlin
  val bgBitmap = remember(bgRes) {
      try {
          BitmapFactory.decodeResource(bgContext.resources, bgRes)?.asImageBitmap()
      } catch (e: Exception) {
          null
      }
  }
  ```
- 他のプロジェクトでも使える知識: Compose の `painterResource()` は端末・OSの
  組み合わせによってリソースID解決に失敗し `Resources$NotFoundException` で
  クラッシュすることがある。特定の画像だけで再現し原因が絞り込めない場合は、
  疑わしい機能（BGMなど無関係に見えるものも含む）を一つずつ無効化して
  切り分けるのが有効。Composeのリソース系APIで解決できない場合は、
  `BitmapFactory.decodeResource()` のような、より低レベルで確実なAPIに
  切り替えるフォールバックが効く。
- 関連ファイル: `app/src/main/java/com/example/lovemanpo/MainActivity.kt`
  （`HomeScreenContent` 周辺、コミット `5bc184f`, `6e2bf63`, `9d8c897`, `9269ca4`）

## MIUI（Xiaomi端末）の強制ダークモードによる起動時クラッシュ

- 発生日: 2026-07-16
- 対象プロジェクト: ラブ万歩計
- 環境: Xiaomi / MIUI端末（強制ダークモード機能が有効な端末）
- エラーメッセージ: `Resources$NotFoundException`（Resource ID #0x0）
- 発生した操作: アプリ起動直後
- 原因: MIUIの「強制ダークモード」機能が、アプリの画像リソースをダーク表示用に
  変換しようとして失敗し、存在しないリソースIDを参照してクラッシュする。
- 試したこと: （原因がMIUI固有の強制変換機能と特定できたため、直接対策を実施）
- 最終的な解決方法: `28f88a6` にて `res/values/themes.xml` のテーマに
  `<item name="android:forceDarkAllowed">false</item>` を追加し、MIUIの
  強制ダークモード変換の対象から外した。
- 他のプロジェクトでも使える知識: 詳細は `docs/shared/エラー解決集.md` の
  同名項目を参照。Xiaomi/MIUI系ROMをターゲットにする場合は最初からテーマに
  `forceDarkAllowed=false` を入れておくと予防できる。
- 関連ファイル: `app/src/main/res/values/themes.xml`

## WardrobeCostumeCard のコンパイルエラー（誤字混入）

- 発生日: 2026-07-13
- 対象プロジェクト: ラブ万歩計
- 環境: 開発環境（ビルド時のコンパイルエラー、実機クラッシュではない）
- エラーメッセージ: コンパイルエラー（構文エラー）
- 発生した操作: `WardrobeCostumeCard` 関数の編集後のビルド
- 原因: `Box(g` のように、コード編集時に余分な文字 `g` が誤って混入していた
  （AIエージェントによる自動編集時のタイプミス、または編集競合によるものと
  推測される）。
- 試したこと: （誤字を目視で特定し直接修正）
- 最終的な解決方法: `39dbb19` にて `Box(g` → `Box(` に修正。
- 他のプロジェクトでも使える知識: AIエージェントにコード編集を任せている場合、
  無関係な文字の混入によるコンパイルエラーが起こることがある。編集直後は
  必ずビルドが通ることを確認してからコミットする習慣が有効。
- 関連ファイル: `app/src/main/java/com/example/lovemanpo/MainActivity.kt`
  （`WardrobeCostumeCard` 関数、コミット `39dbb19`）

## 補足: コミットタイトルと実際の変更内容が一致しない例

「Fix home screen startup crash」というタイトルのマージコミット（`6ba7dbe`）は、
実際には `codex refactor`（`1be07d8`, `HomeScreenContent` の引数を
`HomeScreenUiState`/`HomeScreenActions` にまとめるリファクタ）ブランチと、
天気予報の地名表示（`a9d4a19`）ブランチのマージコンフリクト解消のみで、
具体的なクラッシュ修正内容は含まれていなかった。実際の起動時クラッシュの
原因と修正は、上記2件（ホーム画面背景画像／MIUI強制ダークモード）で
既に完了していた。コミット履歴から経緯を調べる際は、タイトルだけでなく
diffの中身まで確認すること。詳細は `未解決の問題.md` の
「開発プロセス上の注意点」も参照。
